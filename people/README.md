# TechStore People — команда магазина

Самостоятельное веб-приложение для практических работ 7–8: сотрудники магазина техники, стоимость результата и сравнение команды. Визуальный стиль согласован с TechStore 2. Чистые HTML, CSS и JavaScript; внешних библиотек, шрифтов и сетевых сервисов нет.

Основная папка: `/Users/nikita/Downloads/Основы/Frontend/Зяйкин/7-8Пр`. Модуль общего проекта: `/Users/nikita/TechStore 2/people/` (страница `people/index.html`). Его можно открыть отдельно; переход в основной магазин предусмотрен в интерфейсе. Данные команды хранятся независимо от каталога, корзины и избранного TechStore.

## Запуск

Откройте `index.html` двойным щелчком. Сборка и установка зависимостей не нужны. Нужен современный браузер с поддержкой `<dialog>`, классов и `localStorage`.

При необходимости запустите локальный сервер из этой папки:

```sh
python3 -m http.server 8788 --bind 127.0.0.1
```

Откройте <http://127.0.0.1:8788>. Данные страницы, открытой как файл, и страницы на локальном сервере могут храниться отдельно: это разные адреса для браузера.

## Как пользоваться

- «Добавить сотрудника» открывает форму ФИО, должности, зарплаты и эффективности. Фамилия — первое слово ФИО; укажите как минимум фамилию и имя.
- Карандаш изменяет запись, корзина удаляет её после подтверждения. Сразу после удаления доступна отмена. Коэффициент эффективности можно изменить нажатием на него в таблице.
- «Рассчитать утилизацию» вычисляет `зарплата / эффективность` и сортирует сотрудников по возрастанию результата. Например, `90 000 / 1,20 = 75 000 ₽/ед.` Чем меньше показатель, тем меньше стоимость единицы эффективности.
- Минимум выделен зелёным фоном, максимум — красным. Если одинаковый минимум или максимум у нескольких сотрудников, выделяются все такие строки. Когда все показатели равны, используется нейтральное выделение. Сравнение относится ко всей команде и сохраняется при поиске.
- Поиск находит часть фамилии, не учитывает регистр и различие «е/ё». Клавиша `/` переводит фокус в поиск. Сортировка также доступна по фамилии, зарплате и утилизации.
- Кнопка скачивания экспортирует **всю команду** в файл `TechStore — команда.csv`, независимо от поиска. До расчёта столбец утилизации пуст; после расчёта содержит значения. CSV сохраняется в UTF-8, с разделителем `;` и защитой текстовых ячеек от интерпретации как формул.

При первом запуске показаны шесть демонстрационных сотрудников магазина: руководитель, консультанты, сервисный инженер, логист и координатор заказов. Все изменения сохраняются только в `localStorage` этого браузера под ключом `techstore-people-zyaykin-v1`; серверу и третьим лицам данные не передаются. Очистка данных сайта удаляет список. Если браузер запрещает сохранение, интерфейс сообщает об этом и продолжает работать в памяти вкладки; CSV позволяет сохранить копию. Повреждённые сохранённые данные заменяются демонстрационными с уведомлением. Намеренно очищенная команда остаётся пустой после перезагрузки.

Зарплата допускает значения от 0 до 1 000 000 000 ₽. Эффективность — коэффициент от 0,001 до 100; форма принимает тысячные доли. `1,00` означает базовый уровень, `1,20` — на 20% выше него. Нулевая и аномально малая эффективность отклоняются: деление на ноль и переполнение результата недопустимы.

## Где выполнены требования

| Требование | Реализация |
| --- | --- |
| Класс и свойства в конструкторе | `employee.js`: `Employee.constructor`, геттеры `id`, `fullName`, `position`, `salary`, `efficiency` |
| Общие методы прототипа | `Employee.prototype.update`, `getUtilization`, `getSurname`, `toJSON`; синтаксис класса создаёт их в прототипе |
| Приватные свойства через замыкания | `privateRecord` в конструкторе; `read` и `write` замыкают его, а закрытый `WeakMap` связывает доступ с экземпляром |
| Стрелочные функции и `this` | `Employee.getSummary` захватывает `this` конструктора; в `app.js` стрелки обработчиков из `init` сохраняют `this === app` |
| Обычный `this` и `bind` | `app.js`: `init` регистрирует `onEmployeeSubmit.bind(this)` и `onEfficiencySubmit.bind(this)` |
| Добавление и редактирование | `app.js`: `openEmployee`, `onEmployeeSubmit`; `createEmployeeStore.add/update` создают или изменяют `Employee` |
| Удаление и отмена | `app.js`: `openDelete`, `confirmDelete`; замыкание отмены удерживает удалённую запись |
| Расчёт, сортировка и динамическая таблица | `app.js`: `calculate`, `getExtremes`, `render`, `renderRow`, `renderInsights`; `Employee.getUtilization` считает отношение |
| Поиск по фамилии | `app.js`: фильтрация в `render` вызывает `Employee.getSurname` |
| Сохранение без библиотек | `employee.js`: `createEmployeeStore`, `save`; встроенный API `localStorage`, отдельный ключ `techstore-people-zyaykin-v1` |

У обычного метода `this` зависит от способа вызова. Когда браузер вызывает обработчик формы, его `this` обычно указывает на форму. `bind(app)` создаёт функцию с закреплённым `this === app`, поэтому обработчик обращается к нужному хранилищу. `call` и `apply` задают `this` для одного вызова обычной функции.

У стрелочного `getSummary` собственного `this` нет: он захвачен из конструктора. Вызов извлечённой функции работает без `bind`, а `call(другойОбъект)` не заменяет захваченный `this`. В отличие от методов прототипа, такая стрелка создаётся отдельно для каждого экземпляра. Эти различия объяснены комментариями в коде.

## Проверка

Автоматические тесты модели требуют только установленный Node.js:

```sh
node --test tests/model.test.cjs
```

Тесты проверяют валидацию, приватность данных, атомарность редактирования, методы прототипа, лексический `this`, `bind/call`, восстановление экземпляров, сохранение пустого списка, ошибки хранилища, повреждённые данные, одинаковые показатели, уникальность идентификаторов и изоляцию от данных магазина.

Пример для консоли браузера:

```js
const employee = new TeamModel.Employee({
  fullName: 'Иванов Иван Иванович', position: 'Дизайнер',
  salary: 90000, efficiency: 1.2
});
Object.getPrototypeOf(employee) === TeamModel.Employee.prototype; // true
employee.hasOwnProperty('getUtilization'); // false: общий метод прототипа
employee.hasOwnProperty('getSummary'); // true: собственная стрелочная функция
employee.getUtilization(); // 75000
const summary = employee.getSummary;
summary.call({ fullName: 'Другой сотрудник' }); // по-прежнему Иванов
const calculate = employee.getUtilization.bind(employee);
calculate(); // 75000
```

Ручная проверка интерфейса:

1. Добавьте сотрудника с зарплатой 90 000 и эффективностью 1,2. Рассчитайте: ожидается 75 000 ₽.
2. Измените зарплату и коэффициент через оба окна; проверьте обновление строки, сортировки и итогов. Убедитесь, что эффективность 0 отклоняется.
3. Создайте совпадающие минимумы/максимумы, затем сделайте показатели всех сотрудников одинаковыми; проверьте цвета и нейтральное состояние.
4. Найдите сотрудника по части фамилии, измените регистр и попробуйте «е/ё». Очистите поиск.
5. Удалите запись, отмените удаление, перезагрузите страницу. Проверьте сохранение. После удаления всех сотрудников перезагрузка должна оставить пустую таблицу.
6. Скачайте CSV с активным поиском: файл должен содержать всю команду. Проверьте ФИО и числа в текстовом редакторе или табличном приложении.
7. Проверьте навигацию клавишами Tab, закрытие окон Escape, блокировку прокрутки фона открытого окна, ширины телефона и компьютера. При запрете хранилища ожидается предупреждение и работа в пределах вкладки.
8. Откройте модуль из основного TechStore и вернитесь в магазин. Изменение команды не должно менять каталог, корзину и избранное; их ключ `techstore-v1` этот модуль не записывает.

Ручные сценарии выше — инструкция для воспроизведения; сам этот документ не подтверждает прохождение браузерной проверки.
